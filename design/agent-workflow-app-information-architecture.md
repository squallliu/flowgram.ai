# FlowGram 项目工程与 App 信息架构

状态：已按确认的交互小样完成 App 主工作区与工程存储改造。当前实现项目目录创建 / 打开、独立项目数据库、文件工作流、Session 协议、流程 / 会话 / 运行 / 资源导航、显式会话引用和项目工作区恢复；已移除旧 Task 数据及接口，不做兼容。下文保留完整目标：工程实例句柄、嵌套资源包、内容哈希并发校验、提交恢复日志、完整资源依赖快照、发布 / 导出、产物与工程策略仍待实现，不能视为现有能力。

## 核心决策

项目是一个具有真实根目录、明确工程清单、工作流定义、资源、版本及本地运行状态的 Workflow 工程。会话用于在工程内协作，运行用于执行某一份确定的工程定义。项目、工作流、会话、运行分别具有独立生命周期。

| 对象 | 职责与归属 | 身份与生命周期 |
| --- | --- | --- |
| 项目 Project | 工程、资源解析、配置与权限边界；拥有一个真实根目录 | 清单中的稳定 projectId；创建、打开、关闭、移动、导出 |
| 工作流 Workflow | 工程内可独立编辑、测试、复用和发布的可执行资源 | 稳定 workflowId；目录和显示名称均可变 |
| 会话 Session | 属于一个项目的 Agent 协作上下文；可关联多个工作流与运行 | 稳定 sessionId；轮次、工具调用、输入队列归属会话 |
| 运行 Run | 执行确定的工作流及完整依赖快照 | 稳定 runId；不要求存在会话，子工作流调用产生关联的子运行 |
| 产物 Artifact | 运行生成的文件、表格、图像等内容及来源 | artifactId + 内容哈希；归属运行，可被保留、导出或显式转为项目资源 |

产品统一使用“会话”“新会话”，移除作为独立业务实体的“任务”。会话标题可以表达业务目标，但不再混用任务、轮次和工作流执行状态。

一个项目包含多个工作流、多个会话和多个运行。一个会话可以修改多个工作流，一个工作流可以被多个会话操作。会话只保存引用和协作记录，不拥有工作流定义或结果文件。手动操作、内置 Agent、外部 MCP 都通过同一 Rust Project / Workflow / Execution Services 操作工程。

“工作区”用于描述当前窗口的视图与布局，不另设持久业务层级。一个项目可以有多个可独立运行的入口工作流，不要求人为指定唯一 main 工作流。

## 项目为什么存在

项目代表一份可以独立打开、维护和交付的自动化工程。用户建立的是“订单处理工程”，然后在其中组织审核、通知、公共校验等流程；不是先建立一组聊天，再把聊天产出的图挂在旁边。

划分项目的依据是定义、共享资源、配置、授权与交付边界，而不是会话数量或工作流数量。同一个工程可以暂时只有一个工作流，也可以有多个入口和公共子流程；是否被其他流程调用，是流程之间的关系，不是另一种项目层级。具有独立资源、配置和交付生命周期的自动化，应建立另一个项目，不能仅因两个流程都叫“审批”就放进同一项目。

| 订单处理项目中的内容 | 对用户的含义 |
| --- | --- |
| 审核订单、每日汇总 | 两个可以分别发起运行的工作流 |
| 校验订单、生成通知 | 可被其他工作流调用的公共流程，也可以单独测试 |
| 订单样本、通知模板、连接声明 | 属于项目、可被多个流程引用的资源与配置 |
| 增加大额订单分支 | 围绕一次改进目标持续协作的会话，可同时修改审核和通知流程 |
| 排查昨日汇总异常 | 另一个会话，引用已有运行，不复制运行或工作流 |
| 今天 09:00 的审核执行 | 一次运行，固定当时的完整定义与依赖，运行后仍可追溯 |

“打开项目”打开以上工程整体；“打开工作流”编辑其中一个定义；“新会话”开始一段项目内的协作；“运行工作流”创建一次执行。四个动作的结果不能互相替代。没有任何会话，也必须能完整创建、编辑、测试、运行和导出工程。

## 关系与状态的边界

项目对工作流、会话和顶层运行均是一对多。会话与工作流之间是多对多的引用关系，通过某一轮实际读取、变更或运行的对象记录来源，不增加“会话拥有的工作流”副本。工作流之间通过调用契约组合，子调用在运行树中体现。

| 情况 | 设计规则 |
| --- | --- |
| 会话结束，但工作流还在执行 | 分别显示本轮结束与运行中；不能共用一个 running 状态 |
| 用户直接点击运行或由 MCP 发起 | 运行归属工程与工作流，会话可为空；不创建虚假对话来容纳记录 |
| 会话调用了三个流程 | 保留三个工作流引用和实际运行引用，不自动创建三个会话 |
| 两个会话编辑同一工作流 | 编辑同一工程资源；冲突基于版本处理，不给每个会话暗中复制一份图 |
| 工作流里的 Agent 节点在处理 | 属于 Run / NodeExecution 的活动，在运行详情查看，不自动增加项目会话 |
| 关闭工作流标签 | 只关闭视图，不结束会话、不取消运行、不删除定义 |
| 归档或删除会话 | 只处理协作历史，不级联删除工作流、独立运行和已保留产物 |
| 删除被其他工作流调用的定义 | 展示引用并要求处理依赖；历史运行仍指向自己的不可变快照 |
| 关闭或切换项目 | 切换工程视图；后台活动仍属于原工程，不能悄悄转到新项目 |

“任务”不再作为会话与工作流之间的中间实体；用户目标由会话标题和每轮请求表达。也不再把一个工作流运行称为任务。后续实施统一替换旧 Task 对象、接口和界面文案，不保留一套 Task / Session 双命名。

## 产品导航与上下文规则

项目工程边界与导航布局分开。应用使用单一项目侧栏：顶部为项目切换、搜索、收起，接着依次为主页、新建会话、新建工作流、搜索、运行记录和项目资源入口，下方同时展示工作流与会话列表，两组标题右侧均有新建按钮。主页承载当前项目的工作流总览与模板入口，“工作流”“会话”标题只标识分组，具体工作流条目打开独立编辑器。设置固定在底部。项目菜单负责工程切换、新建、打开与详情。工程路径不常驻，不用额外全局面包屑重复项目与会话名称。

会话入口固定消息流与输入在左、按需工作台在右；工作流入口使用独立编辑器，不自动带出会话。两种入口复用同一份工程定义和已挂载画布。各会话独立保存自己的右侧文档与开合状态，工作流独立编辑入口另外记住所选流程。

| 用户动作 | 主工作区与上下文变化 |
| --- | --- |
| 新建 / 打开项目 | 成功取得工程后登记并切换；失败留在打开对话框，不干扰原会话 |
| 侧栏 / 搜索打开工作流 | 进入独立编辑器，不显示会话；已有会话草稿与队列保留 |
| 新会话 | 创建待输入的项目会话视图，右侧默认收起；没有隐含流程目标，首条发送时持久化 |
| 让助手修改 | 默认新会话，可明确选择已有会话；附加该工作流引用，流程保持在右侧 |
| 会话实际操作具体工作流 | 成功调用返回后在右侧打开或复用文档；不改变输入引用、不切到独立编辑模式 |
| 列目录、节点发现或恢复历史 | 不展开工作台，不产生一排文档 |
| 手动切换右侧文档 | 后台同轮更新不抢当前文档 |
| 手动收起工作台 | 同轮更新不重新撑开；新一轮恢复自动跟随 |
| 切换会话 | 恢复该会话历史、草稿、引用、队列及自己的右侧工作台；新会话不继承上一段画布 |
| 打开会话成果 | 工作流或运行在右侧工作台展示，会话保留在左侧 |
| 独立打开运行记录 | 展示结果、当时定义和来源，编辑当前工作流为另一入口 |
| 切换项目 | 恢复目标项目自己的功能、文档与会话；后台活动留在原工程 |

输入引用可以包含工作流、节点、运行与资源。来自工作流入口的引用直接可见；从项目会话开始时由用户明确附加，不能根据最后打开的画布猜测。提交输入后固定本次引用及版本上下文；后续 UI 切换不会改写已提交请求。Agent 进行写入时仍须读取并校验目标最新修改标识，提交时的引用不等于获得覆盖后续编辑的权利。

当前项目决定可访问的工程范围；当前文档决定主区展示；会话输入引用决定本次 Agent 请求的目标；选中的运行决定结果视图。以上状态分别管理，不能再次用三个独立全局 ID 临时拼成一个页面，也不能用“最近运行”自动覆盖用户正在回看的结果。

## 改造前的问题与仍待完成的工程能力

- Project 只有 id、name、createdAt，缺少根目录、工程清单与资源解析边界。
- 全局 SQLite 把项目、会话、工作流和运行保存在同一处；工作流只有最新 schema_json 和自增 revision。已有持久化，但没有独立工程的可移植定义。
- 顶层运行保存了主流程快照；子工作流执行时读取当前工作流定义，尚未冻结完整依赖。
- outputs 与事件数据主要作为 JSON 字符串存入数据库，缺少统一的产物对象、大小边界、保留和引用规则。
- 工作流草稿与字段编辑缓冲部分依赖 sessionStorage；浏览器状态不是工程数据的可靠归属。
- 旧设计把项目描述成侧栏分组，默认从任务开始，导致工程资源与对话导航互相牵制。

以上记录改造前的架构问题，其中项目目录、工程内存储与独立导航已落地；工作流传递依赖的版本与内容哈希已冻结；完整资源依赖冻结、产物和可靠字段缓冲仍是缺口。下文描述目标规范，实施范围以上方状态为准。

## 项目工程规范

### 创建与打开

“新建项目”创建一个完整工程目录；“打开项目”打开包含工程清单的目录。用户可以选择位置，也可以使用应用管理的默认位置。使用默认位置仍然创建完整工程，不生成没有目录的数据库项目。

应用级注册表只保存最近打开的项目、目录授权和设备偏好。项目定义及运行数据不依赖这份注册表：重新打开同一目录即可找回工程。项目可在没有 Git 的情况下使用，也能直接纳入 Git。

一个窗口只有一个当前项目。切换项目恢复该项目的标签、会话和画布；后台运行继续归属原项目，不随窗口选择改变。应用设置与项目设置分开：前者管理外观、语言和连接配置，后者管理工程参数、连接绑定、运行限制与数据保留。

projectId 是工程清单中的逻辑身份；后端打开目录后分配 projectHandle，定位本机已授权的工程实例。移动目录通过重新定位恢复；同一真实目录经符号链接或不同路径打开时复用同一实例。相同 projectId 出现在不同目录时分别识别工程实例，不合并数据库、会话或运行；App 中的“复制项目”创建新 projectId，并保留项目内工作流 ID 与内部引用。

### 标准目录

```text
customer-operations/
├── flowgram.project.json             工程清单
├── AGENTS.md                        可选：工程协作规范，在 UI 中编辑
├── workflows/                       工作流目录；可按业务建立分组
│   ├── orders/
│   │   └── review-order/             一个工作流的完整资源包
│   │       ├── workflow.json        工作流文档
│   │       ├── prompts/             可选：提示词资源
│   │       ├── scripts/             可选：代码节点资源
│   │       └── tests/               可选：输入样本、断言和资源
│   └── shared/
│       └── validate-order/
│           └── workflow.json
├── assets/                          项目共享的输入文件、模板和静态资源
├── config/
│   ├── parameters.json              可移植的非敏感参数和默认值
│   └── connections.json             逻辑连接声明，无凭证或设备绑定
├── releases/                        发布版本：不可变、可移植的完整依赖包
└── .flowgram/                       项目本地数据，默认不进入 Git
    ├── state.sqlite                 会话、运行、事件、引用与索引
    ├── objects/sha256/              不可变快照、输入输出与产物内容
    ├── local/                      本机连接绑定与设备专属参数
    ├── journal/                    文件提交与恢复日志
    ├── tmp/                        执行临时目录，不能作为最终产物
    └── cache/                      可重建的预览等缓存
```

可选目录按需创建，不生成空目录来增加复杂度。一个工作流对应一个资源包目录，其中 workflow.json 是定义入口；提示词、代码和测试与它一起移动、复制和导出。项目根目录的 workflows 分组映射为 UI 中的文件夹，资源包目录映射为一个工作流，不暴露内部 workflow.json 和扩展名。

### 工程清单

flowgram.project.json 明确包含：格式版本、projectId、名称与说明、固定入口目录、运行时与节点契约要求、默认参数/连接声明位置、工程级策略。不能用它维护第二份工作流清单；工作流目录扫描与 ID 索引可重建，避免清单和真实文件重复维护。

设备路径、模型密钥、浏览器标签、当前会话、运行状态和数据库内容不进入清单。projectHandle 仅为运行中访问句柄，不写入工程文件，也不能作为持久引用。

AGENTS.md 承载项目说明、工作流组织约定、命名和测试要求，UI 展示为“协作规范”；不要求业务用户操作 Markdown。应用生成的默认规范使用英文，用户自行填写的内容原样保留。会话接收输入时记录使用的规范版本；工作流 Agent 节点若使用该规范，必须把它作为执行依赖纳入快照。规范文件不能扩大文件访问范围或覆盖后端授权策略。

资源操作使用相对位置或逻辑引用，后端校验规范化后的路径仍位于授权工程根目录内，不能通过上级路径或符号链接越界。外部文件经显式导入成为项目资源；Agent 和工作流脚本不能直接改写 .flowgram 数据库、恢复日志或凭证存储。项目工程可被独立工具读取，但产品中的保存和运行都由相同 Rust 服务完成校验。

### 工作流文档

| 内容 | 规范 |
| --- | --- |
| 文档头 | formatVersion、workflowId、显示名称、说明 |
| 公共接口 | 输入 Schema、输出 Schema，字段名称与类型明确 |
| 可执行图 | 节点、静态端口、连线、分支/循环作用域、参数与资源引用 |
| 资源声明 | 提示词、脚本、输入资源、逻辑连接和可调用工作流 |
| 共享画布布局 | 节点位置、容器位置等工程编辑信息；不参与执行语义哈希 |
| 测试 | tests 下声明输入、预期输出或结构断言；不混入运行历史 |

稳定 ID 是身份；显示名称、文件夹和资源包路径是可修改的组织方式。工作流名在不同分组可以相同，同一工程内 workflowId 不能重复。文档格式固定字段顺序、稳定节点/边序列化，不写设备时间、绝对路径或每次保存都变化的临时值，保证可审查的 Git 差异。

后端使用文档内容标识校验并发编辑，不能只靠全局自增数字。文档修改标识包含共享画布布局；执行 revision 只计算执行定义和相关资源。修改节点位置不会伪装为业务执行变化。视口、选中状态、面板尺寸和打开的页签属于本机视图状态，不写入工作流文档。

图可以尚未完成并被保存为草稿；“保存成功”与“可执行”是两个状态。无法组成有效字段值的输入缓冲由后端按工程、工作流和字段保存为待完成编辑，明确标记，不能静默把残缺字符串写成有效配置。运行时提示处理相关未提交编辑，不使用浏览器里偶然存在的值。

## 工作流引用与版本

### 调用契约

调用子工作流的节点明确选择目标 workflowId、版本策略、输入映射、输出映射、超时及错误处理。界面用项目分组和名称帮助选择，持久化引用使用稳定 ID，不使用名称或绝对路径。改名、移动目录不破坏引用；删除前展示反向引用并阻止留下悬空调用。

目标工作流通过公开的输入/输出 Schema 接收和返回数据，不能直接读取调用方节点变量或会话上下文。需要共享的参数与连接必须在工程配置和调用上下文中明确声明。改变公共接口时，校验所有调用点并定位受影响的字段和连线。

| 选择方式 | 编辑和执行规则 |
| --- | --- |
| 当前工程版本 | 编辑时引用目标当前工作副本；准备运行时一次性解析并固定 |
| 固定发布版本 | 明确引用某个不可变 releaseId；更新由用户或 Agent 显式执行 |

禁止执行到子流程时再查“最新版本”。发布主流程时，把它依赖的当前工程版本全部转为确定快照，固定版本依赖继续引用其原始确定内容。发布后目标草稿的任何修改都不改变旧发布版本。

同一工程内支持组合调用；跨项目复用通过导入完整依赖包完成，不能引用另一项目的本机路径或依赖它恰好处于打开状态。跨项目在线依赖/包注册服务尚不属于本模型的已实现能力，不设置虚假的入口。

### 执行依赖包

每个发布版本保存在 releases/<workflowId>/<releaseId>/，包含不可变清单、完整工作流定义、接口、提示词/脚本以及所引用静态资源的实际内容，内容哈希用于校验。包必须可独立拷贝，不能只引用被 Git 忽略的 .flowgram/objects。目录移动或删除当前工作副本后，已发布的依赖包仍能被校验、导入和运行。

运行前由 Rust Snapshot Builder：解析全部传递依赖，校验接口、端口、作用域和所需资源，收集内容哈希，生成 Execution Manifest。保存根流程及依赖的 revision、资源哈希、运行时/节点契约版本、非敏感参数快照、实际模型标识及连接绑定标识。密钥只在调用时解析，不进入快照、发布包或日志。

工作流调用图拒绝递归依赖，循环使用明确的循环节点。对于声明式调用，完整闭包在启动前固定；Agent 节点能够选择的工作流工具也必须具有明确授权及版本范围，不能用动态工具调用绕过版本规则。需要新范围的动态运行必须作为新的、显式关联的运行创建，使用自己的 Manifest。

项目资源引用区分工作流包内资源、project://assets 下的共享资源和运行产物引用。静态文件在准备运行时固定字节内容。外部数据库、远程服务和实时流记录来源及实际版本信息；它们不自动具备快照能力。保留完整定义及输入可以复核一次执行，不能承诺模型和外部业务调用具有确定性重放结果。

## 会话、运行与结果存储

### 会话

会话严格归属一个项目，包含 Turn、输入队列、消息/工具 Item、上下文引用和所发起运行的链接。会话可面向一个工作流，也可面向整个工程；“当前画布”与“本轮目标”分别表达。

输入被接收时固定其工程、工作流/节点/版本引用。切换标签、画布或项目不改变运行中轮次的操作对象。排队输入也保留提交时的引用，不能在消费时替换为用户后来打开的工作流。所有变更工具显式指定目标与预期修改标识。

归档/删除会话不删除工作流、不撤销外部业务操作，也不自动取消独立运行。若会话仍有运行或待确认事项，操作界面明确说明处理范围。会话不是工程文件的所有者。

### 运行

手动、会话、MCP、定时器等来源都可以创建 Run。Run 直接归属项目、工作流和固定执行快照；origin 单独保存来源、可选 sessionId/turnId/toolCallId。工作流改名或会话删除不会丢失执行来源摘要。

每次子流程调用生成 childRunId，关联 rootRunId、parentRunId、callerNodeExecutionId。每个节点执行具有 nodeExecutionId，并记录工作流 revision、循环/分支路径与 attempt。重复调用同一工作流、循环多次执行同一节点时，都能准确定位其输入、输出、等待、失败和取消状态。

运行列表默认展示顶层运行，子运行在执行树中查看，避免把一次业务运行展开成大量并列记录。节点单测也是有明确类型和独立输入的运行，不冒充完整工作流运行。

### 结果与产物

| 数据 | 权威存储 | 读取规则 |
| --- | --- | --- |
| 会话、轮次、工具状态 | .flowgram/state.sqlite | 事务写入、稳定序号、有界分页 |
| Run / NodeExecution 状态及关系 | state.sqlite | 状态不从日志文本推断 |
| 运行清单与定义快照 | objects 不可变内容，SQLite 保存清单引用 | 主流程与完整依赖使用同一份确定清单 |
| 小型结构化输入/输出 | 数据库内联 Value | 建议上限 64 KiB；接口返回明确数据类型 |
| 大型 JSON、二进制、文件产物 | objects 内容寻址存储，SQLite 保存元数据与引用 | 返回 ValueRef / ArtifactRef，按需下载/预览，不塞进工具结果和消息流 |
| 发布定义包 | releases 下完整不可变包 | 独立可移植，不依赖运行历史数据库 |
| 预览、搜索投影、缩略图 | 可重建索引或 cache | 缺失不等于丢失原始数据 |

Artifact 元数据包含名称、类型、MIME、大小、哈希、生成它的 runId/nodeExecutionId、可用/已清理状态。大结果提供分页或下载，界面预览默认有界；消息流展示引用和摘要，不复制整份结果。运行中间值、最终值和文件使用统一引用契约。

“最近运行”只是列表排序，不能作为变量引用或缓存的隐式身份。表单样本和节点结果明确绑定 Run + NodeExecution + revision；工作流变化后显示样本版本差异，不能把旧输出当作当前定义的结果。

需要复用输出时选择某次产物，或执行“保存为项目资源”，生成 assets 内的正式资源并记录来源。不要让后续工作流依赖某个临时下载路径或另一个会话的临时目录。

保留策略区分运行记录和内容保留：可显式保留的重要结果、运行中的内容、已发布依赖包和被项目资源使用的内容不能被自动回收。内容按全部引用可达性回收；删除普通运行后有共享引用的字节仍保留。自动清理后仍存在的运行摘要明确显示“详细结果已清理”，不显示成执行失败。

默认保留完整运行结果，项目显式启用期限或空间策略后才执行自动清理；项目设置展示当前占用及各类内容的保留范围。手动批量清理使用相同引用规则，不能只按文件时间删除对象目录。

## 持久化与工程操作

### 每类数据只有一个写入权威

工作副本定义以工程文件为准；工作流目录索引是投影。会话和运行状态以项目 SQLite 为准；不能宣称删除该数据库可以重建全部历史。发布包以自身不可变文件为准。大内容以校验通过的不可变对象为准，数据库保存其身份、状态和引用。

应用级存储只包含项目注册、设备连接配置/凭证与 UI 偏好。SQLite WAL 等伴随文件属于数据库一致性的一部分；备份使用受控快照，不能在运行中只复制主 sqlite 文件。

### 文件和索引的一致性

UI、Agent 和 MCP 共用 Project Repository 单写入口。保存携带预期文档标识；同项目内变更串行提交，其他客户端修改时返回冲突及差异，禁止最后写入覆盖。

同一真实工程目录由一个后端持有进程级写锁；多个窗口及 MCP 客户端连接同一个写入服务。另一后端不能自行打开第二套写调度器，不能依靠不同路径或重复 projectId 绕过该锁。

保存协议为：写入持久化事务意图和临时文件 → 校验/同步内容 → 原子替换目标 → 更新索引与历史引用 → 标记提交完成。成功回执只在协议完成后返回。跨文件操作有项目事务日志及恢复规则，不假定 SQLite 和文件系统之间天然存在一个原子事务。

后端启动先恢复未完成事务，再接受编辑和运行。通过操作 ID、预期前后哈希和磁盘状态判断完成、回滚或冲突；不能覆盖恢复期间出现的外部修改。未提交内容不能参与发布或执行。

Git checkout、外部修改和文件移动触发工程重载及全量校验；批量导入/检出期间暂停新快照生成。遇到未解决冲突、重复 ID、无法解析文档或快照采集期间仍在变化的依赖，返回具体问题，不继续从旧索引执行。由 backend 生成的确定 Manifest 才能交给 Runtime，Runtime 不实时扫描工作目录。

### 导入、导出、Git 与备份

- 工程源码包含清单、workflows、assets、非敏感 config 及 releases。Git 默认忽略 .flowgram，克隆得到工程定义和发布版本，创建新的本地会话/运行存储。
- 导出工作流包含目标及传递依赖、资源和接口。导入时检测 ID 与内容冲突；创建副本会重建目标 ID 并重写整个依赖包的内部引用，不只复制一个 JSON。
- 导出工程定义包含完整源码和必要发布依赖；完整工程备份额外包含一致的 SQLite、内容对象、会话和运行。两者在界面中明确区分。
- 本地连接绑定和密钥不进入可分享定义包；在另一设备打开时显式绑定缺失连接。移动同一工程保留定义、会话和历史；设备凭证仍由设备管理。
- Git 回滚工作副本不会回滚运行历史。旧运行继续指向原快照；从历史恢复工作流会形成新的工作副本修改，不改写过去的执行。
- 目录被移走或存储不可写时显示项目不可用，禁止静默创建同名空数据库或回退到应用全局工程。

## 由工程模型推导的 App 导航

```text
FlowGram
├── 当前项目选择器               新建 / 打开目录 / 最近项目
├── 工作流
│   ├── 订单                     业务分组
│   │   ├── 审核订单             一个工作流，不显示内部文件
│   │   └── 生成通知
│   └── 公共流程
│       └── 校验订单
├── 会话                         新会话 / 最近 / 归档
│   ├── 优化订单审核
│   └── 排查昨日执行
├── 运行记录                     当前项目的顶层运行
├── 资源                         输入文件、模板、保留产物
├── 项目设置                     参数、连接绑定、执行与保留策略
└── 应用设置                     模型配置、外观、语言、设备连接
```

导航只展示当前工程的内容；项目通过选择器切换，不在一个长侧栏中同时展开所有项目的工作流和会话。工作流是首要资源入口，会话与运行均有独立入口。项目级运行列表、工作流历史、会话成果卡引用同一个 Run，不产生三套结果。

新窗口没有项目时，展示“新建项目 / 打开项目”和最近工程。打开项目恢复上次工作区；新工程展示工作流空状态，提供“新建工作流”和“让助手搭建”，不自动创建空会话或默认示例流程。

### 主工作区

工作区使用工作流、会话、运行三个明确的文档类型：工作流页以画布为主，会话页以对话为主，运行页以执行树和结果为主。各页均显示所属项目及对象名称，保留独立的选中项、视口和结果上下文。

- 打开工作流：直接编辑；需要协作时展开会话区域，明确选择已有会话或新会话。只有实际提交输入才创建会话。当前工作流引用显示在输入框中。
- 打开会话：呈现原轮次历史；从成果卡打开工作流或运行。可以与画布并排，当前选择的工作流不隐式改变已提交轮次的目标。
- 打开运行：呈现快照版本、来源、状态、子运行、节点执行、输入输出和产物；“查看当时定义”读取快照，“编辑当前工作流”是独立动作。
- 多标签允许打开多个工作流；会话切换不关闭工作流，工作流关闭不归档会话。不能用一个全局 workflowId/selectedRunId 决定所有页签。
- 工作流底部运行面板是选中运行的快捷视图，支持隐藏并保留高度；完整运行详情仍可独立打开。多选、节点配置和布局继续遵循现有设计规范。
- 资源与项目设置是低频目的地，不强行把原始目录树、终端和源码编辑器塞给业务用户。高级操作可查看工程位置和导出定义，但普通使用不要求理解 JSON 或文件扩展名。

轮次、工具调用、运行中输入和待处理事项继续遵循 [对话与轮次设计](conversation-information-architecture.md)，其旧“任务”命名在实施时统一替换为“会话”。

## Rust 领域边界与统一工具

| 服务 | 唯一职责 |
| --- | --- |
| Project Repository | 目录打开/授权、清单与资源解析、文件事务、索引和冲突 |
| Workflow Service | 工作副本、接口、引用、测试定义、重命名/移动/复制/删除 |
| Snapshot / Release Service | 依赖闭包、版本校验、Manifest、不可变发布包 |
| Session Service / Agent Runtime | 会话、Turn、Item、队列、Agent 上下文和工具生命周期 |
| Execution Service / Workflow Runtime | 根/子运行、节点执行、固定清单调度、取消与恢复边界 |
| Value / Artifact Store | 内容、元数据、引用、预览、导出与保留/回收 |

所有 API 和 MCP 变更都携带确定工程上下文，工具不能根据 UI 当前选中项目猜测目标。外部 MCP 连接绑定已授权项目句柄，工具内再校验 workflowId/releaseId/runId 的归属。内置 Agent、手动 UI 与 MCP 的差异只在调用来源和展示方式，不在保存、版本或执行逻辑。

Rust 后端独立负责以上能力；Tauri 只提供目录选择、打开位置等桌面入口。浏览器和外部客户端通过相同公开 API 使用工程能力。Agent 默认提示和工具描述继续使用英文，UI 支持中英文；静态端口、循环和分叉要求保持不变。

## 旧数据清理与切换规则

本轮只完成设计。实施新的工程存储并完成以下验收后，统一替换原型数据模型；不开发旧表迁移、不保留双写、不提供隐式兼容读取，也不将旧 JSON 伪装成新格式。

清理范围：旧原型项目、任务/会话、轮次及队列、工作流、运行、事件、测试记录、旧快照与孤立产物；清理引用旧对象的浏览器项目/会话/工作流选择、输入草稿、节点编辑缓冲和缓存。停止属于该实例的旧执行及写入者后再清理明确归属的旧数据库、WAL/SHM 及原型临时内容，不扫描或删除用户目录里的其他数据库。

实施作为一次完整的模型切换交付：工程存储、统一工具与 API、对象导航、会话引用和运行追踪同时采用新归属规则；不交付仍由旧全局选择驱动的新外壳，也不先删掉当前数据再继续使用旧模型。清理完成后启动进入新建 / 打开工程，不自动重建旧验收项目、聊天或示例工作流。

保留模型连接配置、凭证以及语言、主题、动效和无关布局偏好。项目级绑定按新工程显式建立。旧模型直接判为不支持，提供创建/打开新工程的明确路径；不静默加载旧内容、不自动生成聊天示例。清理执行结果需记录范围、剩余配置和新工程位置。

## 完整验收条件

1. 在独立目录创建工程，脱离 UI 使用 Rust API 打开、校验、修改并运行；应用注册表删除后仍可重新打开。
2. 没有会话即可创建、编辑和运行；一个会话修改多个流程、多个会话操作同一流程时，归属与并发冲突明确。
3. 重命名和移动工作流包保持引用；删除被引用流程、复制依赖包、跨项目导入时，不产生悬空或误指对象。
4. 主流程运行途中修改子流程、提示词、脚本和资源，当前运行仍执行原快照；旧发布版本同样不漂移。
5. 相同子流程被多次调用、在分支和循环中执行时，执行树、输出和重试记录可准确定位。
6. 产生大 JSON、文件和大量节点事件时，API 有界返回、界面按需加载，结果可追溯、导出和显式转为项目资源。
7. 强制退出、保存阶段崩溃、文件外部修改、Git 检出、目录移动、重复工程 ID、磁盘失败均具有明确恢复或冲突结果。
8. 归档/删除会话不影响工作流与保留产物；内容清理不会删除运行中、已保留或仍有引用的对象。
9. 工程定义导出、单工作流导出、Git 克隆、完整备份恢复在新位置验证；凭证缺失要求重新绑定，不能偷用另一项目连接。
10. 中英文、主题切换与布局操作不重建工程实例、丢失编辑或改变正在运行的目标。旧原型数据清理后保留模型连接和设备偏好。

以上是一个完整工程模型的验收范围，不以先补几个目录或改侧栏名称代替。

## 部署信息架构（当前实现）

部署是设置里的独立全局模块，包含发布、凭证、运行服务。设置不划分“当前项目”，项目侧栏不增加服务入口。发布配置绑定所属项目，一张卡片承载公开工作流、版本历史和多个目标的部署事实；新版本沿用卡片，未发布配置显示在草稿分组。新建／编辑为二级页面；工作流的发布快捷入口带入项目及工作流，不改变原工作区视图。

全局凭证可允许全部或指定项目，项目发布仅引用凭证。Rust 同时校验凭证用途与范围，执行时再次检查；对外调用授权另行限定发布目标及公开工作流。运行服务连接和管理凭证独立于当前项目，业务系统消费已部署版本，无需保持桌面运行。发布详情展示目标实际状态；远程执行复用现有 RunPage 与同一运行快照查询能力。
